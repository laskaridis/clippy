## Codebase Patterns
- Keep the core local workflow documentation in the order: worktree, `.devcontainer/.env`, Dev Containers, `dev-sandbox`, then `make backend-run` for an explicit live backend.
- Use `dev-sandbox` as the Dev Containers service name for the local sandbox, and publish the backend on the same `DJANGO_DEV_PORT` value inside the container and on the host.
- Keep `.devcontainer/.env.example` focused on the minimal localhost contract: `ALLOWED_HOSTS` should cover `localhost`, `127.0.0.1`, and `[::1]`, and per-worktree hostnames should not be documented there.
- Use the active container Python interpreter for bootstrap installs via `python -m pip`, and keep `.devcontainer/bootstrap.sh` as a thin wrapper that delegates setup to `make backend-init` and `make extension-init`.
- Prefer `$(MAKE)` subtarget composition for aggregate Makefile targets instead of shell wrapper scripts.
- Keep `make backend-run` as the explicit Django launch path inside the devcontainer: `cd backend && python manage.py migrate`, bootstrap the admin user with `apps.accounts.bootstrap.ensure_admin_user_from_env`, then run `python manage.py runserver 0.0.0.0:${DJANGO_DEV_PORT}`.
- Backend test wrappers should assume the devcontainer is already prepared and call `python manage.py test ...` directly from `backend/` without re-running runtime bootstrap helpers.
- Backend unit and E2E tests share the same database contract, so run them sequentially against one `DATABASE_URL` instead of in parallel when they point at the same Postgres instance.
- When deleting legacy helper scripts, first neutralize any shell tests that hardcode those filenames so repo-wide reference audits go green before the files are removed.
- Obsolete host-runtime tests can be deleted once their Make-target dependencies are gone; keep repo-wide `rg` audits focused on the code and script surfaces that still matter after the deletion.
- Rewrite `extension/chrome/runtime-config.js` in place from environment values using `WEBCLIPPINGS_API_BASE_URL` first and `DJANGO_DEV_PORT` as the localhost fallback; avoid creating `.local` extension artifacts for local development.
- Extension Playwright helpers should load the checked-in `extension/chrome` directory directly and start the backend with `make backend-run` from the repo root when they need a fallback startup path; do not depend on generated worktree runtime files.
- Keep the extension shared config precedence fixed: runtime config first, the first valid `manifest.json` host permission second, and `http://localhost:8000` last.
- When removing obsolete helper scripts, delete any thin wrappers that still invoke them and scrub live README references before running repo-wide reference audits.
- Keep the feature-delivery gate shell script and its `SKILL.md` description in sync; if the script switches from a wrapper to `make` targets, update the skill text in the same pass.
- Include `.agents/skills/` in repo-wide reference audits for runtime cleanup, because skill wrappers can keep obsolete filenames alive even after code and README cleanup.
