## Codebase Patterns
- Use `scripts/agent-preflight.sh` before edits; branch/worktree compliance is a hard gate and also enforced by git hooks.
- Use Makefile entrypoints (`make backend-test-unit`, `make backend-lint`, `make backend-typecheck`, `make all-verify`) as canonical quality gates for backend/frontend refactor work.
- For the Stimulus migration, assign each interactive component exactly one controller owner and use URL query state plus document-level DOM events for cross-component coordination instead of `window.*` APIs or page-global orchestration.
- For BEM compliance spot-audits, scan component CSS with `rg` to enforce no `[data-component="..."]` styling anchors and keep styling on explicit class contracts.
- For clips list behavior, URL query state (`label`, `panel`, `url`) is the source of truth; UI controls mutate URL parameters and trigger reload/parity through server-rendered context.
- Global style loading order is defined in `backend/webclippings/templates/base.html`: load `static/css/tokens.css` before `static/css/base.css` so shared tokens are available to base and component styles.
- Keep `backend/webclippings/templates/base.html` as a compatibility shim that extends `templates/layouts/base-shell.html` while legacy pages still reference `base.html`; this enables incremental migration without route template rewiring.
- Keep quick-search behavior in a global authenticated component script (`backend/static/js/components/global-auth-quick-search.js`) loaded from `base-shell`, while clips list logic lives in `clips/js/pages/list-page.js` orchestrating clips-scoped component modules.
- Keep clips component JS module basenames aligned with template component basenames (for example `clip-card.html` <-> `clip-card.js`, `label-filter-options.html` <-> `label-filter-options.js`) and wire initialization from `js/pages/list-page.js`.
- When removing legacy root aliases, keep `data-component="<name>"` as the canonical JS ownership hook and remove alias fallbacks in component JS/tests in the same change to avoid split contracts.
- For list-page component JS, pass explicit root elements into component initializers (`init({ root, ... })`) and keep setup-time DOM queries scoped to those roots to avoid document-global coupling.
- Keep clips list cross-component orchestration (drawer/sidebar state wiring and page-level label actions) in `clips/js/pages/list-page.js`; keep `clips/js/components/label-filter-options.js` scoped to label-option-root behavior and expose only minimal query mutation helpers via `window.ClipsListLabelFilters`.
- Keep global authenticated quick-search styling in `backend/static/css/components/global-auth-quick-search.css` loaded from `base-shell`, while clips list route styles are loaded from `clips/pages/list.html` via app `css/components/*` includes.
- When migrating route templates into app `pages/` folders, update all `template_name` references and template assertions together in the same change to avoid silent route/template drift.
- When a Django component partial uses custom filters/tags, add its own `{% load ... %}` in that partial; parent template loads are not guaranteed for isolated component includes.
- For page-specific style extraction, move inline template styles into `static/<app>/css/components/<component-name>.css` scoped by `[data-component="<component-name>"]`, then load that stylesheet via the page template `extra_head` block.
- When composing form templates via `{% include ... with ... only %}`, propagate `csrf_token` explicitly to nested includes so CSRF-protected POST flows continue to work in browser/E2E runs.
- For CSRF regression coverage on server-rendered form pages, use Django `Client(enforce_csrf_checks=True)` and validate both token rendering (`name="csrfmiddlewaretoken"`) and successful token-backed POST flows.
- For frontend parity sign-off, keep a route-by-route Playwright smoke report under `docs/plans/<feature>/manual-smoke-checklist.md` covering desktop/mobile load checks, primary navigation actions, and console/network sanity.
- For incremental BEM rollout, migrate CSS to canonical `<block>__<element>` / `<block>--<modifier>` selectors first and keep temporary legacy class aliases in the same rules until template/JS follow-up tasks land.
- When migrating JS behavior to BEM, toggle canonical modifier classes (for example `--active`, `--collapsed`) instead of legacy `.active`/`.is-*` state classes, or stale legacy classes can keep components visually out of sync after interaction.
- Component template headers are a required contract surface: every migrated component must document `component`, `inputs`, `actions`, `block`, `elements`, and `modifiers`; if a component has no custom BEM contract, set `block/elements/modifiers` to `none`.
- For duplicated component instances on one page (for example sidebar + drawer label options), use instance markers like `data-target-list` in browser tests/selectors so interactions are asserted against the intended root.
- Before removing non-root `data-*` hooks, run an `rg` consumer sweep across templates, JS, CSS, and tests; remove only zero-consumer hooks and preserve active interaction hooks as stable JS contracts.
