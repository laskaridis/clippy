## Codebase Patterns
- Keep Ralph's installable Python package metadata and console-script entrypoint under `ralph/` so the harness stays independent from backend packaging.
- Keep at least one unittest-discoverable smoke test module in `ralph/tests`; an empty discovery tree exits with code 5.
- Keep shared Ralph failure classes in `ralph/errors.py` and import them from there instead of defining module-local exception names.
- Resolve feature folders through `ralph.config.resolve_run_config()` so relative paths are normalized once and required feature files are validated before lifecycle code runs.
- Keep agent backends behind `ralph.agents.base.Agent` and return `AgentResult` with stdout, exit code, and diagnostics metadata instead of raw subprocess objects.
- For Codex-backed adapters, treat the `-o` file as the authoritative payload and keep subprocess stderr in `AgentResult.metadata` for diagnostics.
- Resolve concrete agent backends through `ralph.agents.factory.resolve_agent()` so lifecycle code stays backend-agnostic and unknown identifiers fail through a typed Ralph error.
- Keep run-session persistence behind `ralph.session.RunSessionStore`; store one JSON session per run under `.ralph/sessions/` and treat `current.json` as the authoritative pointer for resume.
- Keep lock staleness checks conservative: only the local host can prove a recorded PID is dead, and remote-host locks stay active until higher-level recovery decides what to do.
- Acquire `.ralph/lock` with an exclusive create or equivalent atomic filesystem primitive so concurrent runs cannot both believe they own the same feature lock.
- Keep lifecycle phase contracts in `ralph/ralph/lifecycle/phases/base.py` as single-shot typed results with a local outcome enum and metadata mapping; do not let phases decide the next phase.
- Keep prompt assets inside the phase package that owns them, and render them through a small phase-local helper instead of a centralized prompt module.
- Keep phase-specific readiness checks inside the owning phase package alongside the prompt helper so phase-local prerequisites stay explicit and do not leak into shared lifecycle validation.
- Normalize CRLF before exact first-line status comparisons in phase-local parsers, and preserve the trailing response body for diagnostics.
- Keep code-phase bookkeeping validation narrow: treat missing task `status` values as pending, count only explicit `completed` entries as finished, and create `ralph.txt` only when the file is missing.
- Keep phase execution wrappers single-shot: render the prompt, invoke the agent once, parse status, validate bookkeeping, and return a `PhaseResult` with metadata instead of prompt or response bodies.
- For fresh run entrypoints, check the current-session pointer and lock state before creating a new session, then keep lock ownership, session creation, and the phase loop inside one `finally`-protected block so a failure cannot strand active ownership.
- Release `.ralph/lock` through an ownership-aware best-effort cleanup helper so `finally` blocks do not mask the original run or resume failure when the lock is absent or already owned by a different session.
- Keep the public CLI as a shared `argparse` subcommand surface that resolves `RunConfig` before resolving the agent and converts `RalphError` subclasses into a single stderr line plus a non-zero exit.
- Keep `ralph/ralph.sh` as a compatibility shim that sets `PYTHONPATH` to the repo-local `ralph/` package root and `exec`s `python -m ralph.cli` after translating legacy flags, so the shell entrypoint stays authoritative only for argument mapping.
- Keep deterministic Ralph test doubles in `ralph/tests/fakes.py`; script `AgentResult` values and controlled exceptions rather than patching subprocesses in each test.
- When testing multi-iteration lifecycle flows, mutate feature-local bookkeeping files between fake-agent invocations instead of monkeypatching orchestrator internals.
- Run Ralph Make targets from the repository root; the tests import the top-level `ralph.tests` namespace package, so `cd ralph && ...` will shadow the namespace and break discovery.
